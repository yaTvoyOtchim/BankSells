# Office Product Catalog Design

## Цель

Сделать продукты управляемыми из приложения, а не зашитыми в код. У каждого офиса могут быть свои активные продукты, свои баллы и свои правила по суммам. Старые продажи должны сохранять баллы и название продукта такими, какими они были на момент продажи.

## Главные решения

- Глобальный справочник хранит сам продукт: код, название, группа, описание, общий статус.
- Офисная настройка хранит правила продукта для конкретного офиса: активность, баллы, требование суммы, учет в плане и порядок показа.
- Сотрудник видит только активные продукты своего офиса.
- Админ и руководители не должны иметь функцию внесения собственных продаж.
- Руководитель офиса может редактировать настройки продуктов только своего офиса.
- Региональный руководитель может редактировать настройки продуктов офисов своего региона.
- Админ может редактировать все продукты и настройки всех офисов.
- Баллы сохраняются в продаже снимком на момент продажи, чтобы старые отчеты не менялись после изменения справочника.

## Роли И Доступ

`EMPLOYEE`

Видит активные продукты своего офиса и создает продажи. Не управляет справочником продуктов.

`TEAM_LEAD`

Не создает продажи. Смотрит продажи своей команды. Видит активные продукты своего офиса. Не редактирует продуктовые настройки в первой версии.

`OFFICE_MANAGER`

Не создает продажи. Смотрит сотрудников и продажи своего офиса. Может включать и выключать продукты для своего офиса, менять баллы, требование суммы, учет в плане и порядок отображения.

`REGIONAL_MANAGER`

Не создает продажи. Смотрит регион и офисы внутри него. Может менять офисные настройки продуктов для офисов своего региона.

`DIRECTOR`

Не создает продажи. Смотрит свою дирекцию. В первой версии только просматривает продуктовые настройки без редактирования.

`ADMIN`

Не создает продажи. Управляет глобальным справочником продуктов, офисными настройками, ролями, офисами и пользователями.

## Данные

### Глобальные Продукты

Таблица `products`.

Поля:

- `id`
- `code`: стабильный технический код, например `PDS`
- `title`: название для интерфейса, например `ПДС`
- `group_name`: группа продукта, например `Инвестиции`, `Карты`, `Кредиты`, `Сервисы`
- `description`
- `archived`: скрыт ли продукт из новых настроек
- `created_by_user_id`
- `created_at`
- `updated_at`

Правила:

- `code` не меняется после создания, чтобы отчеты и история не ломались.
- Название разрешено менять, но продажи уже сохраняют старое название снимком.
- Продукт лучше архивировать, а не удалять, чтобы история продаж оставалась читаемой.

### Офисные Настройки Продуктов

Таблица `office_product_settings`.

Поля:

- `id`
- `product_id`
- `org_unit_id`: офис или отделение
- `active`: показывать сотрудникам этого офиса
- `points`: количество баллов за одну продажу
- `requires_amount`: нужно ли указывать сумму
- `counts_toward_plan`: учитывать ли в плане
- `sort_order`
- `updated_by_user_id`
- `created_at`
- `updated_at`

Правила:

- Один продукт имеет независимые баллы в каждом офисе.
- Один продукт разрешен в одном офисе и скрыт в другом через офисные настройки.
- Если продукта нет в настройках офиса, сотрудник его не видит.
- При создании нового глобального продукта админ может сразу включить его для выбранных офисов или оставить скрытым.

### Продажи

Таблица `sales` должна хранить ссылку на продукт и снимок правил на момент продажи.

Дополнительные или уточненные поля:

- `product_id`
- `product_code_snapshot`
- `product_title_snapshot`
- `product_group_snapshot`
- `points_snapshot`
- `requires_amount_snapshot`
- `counts_toward_plan_snapshot`
- `amount`
- `quantity`
- `client_last4`
- `sale_group_id`
- `org_unit_id`
- `created_at`

Правила:

- Итоговые баллы продажи считаются как `points_snapshot * quantity`.
- Если продукт требовал сумму на момент продажи, продажа без суммы не принимается.
- Изменение баллов в офисной настройке влияет только на новые продажи.
- В отчетах по прошлым продажам используются снимки из `sales`, а не текущие настройки продукта.

## Экран Сотрудника

На экране добавления продажи:

- приложение запрашивает активные продукты офиса с сервера;
- сотрудник вводит последние 4 цифры телефона один раз;
- выбирает один или несколько продуктов;
- для продуктов с `requires_amount = true` появляется обязательное поле суммы;
- продукты показываются в порядке `sort_order`;
- скрытые или архивные продукты не показываются.

Если приложение временно без сети:

- приложение использует последний сохраненный локальный список активных продуктов;
- при сохранении офлайн в продажу кладется снимок из локального списка;
- при синхронизации сервер должен повторно проверить, что продукт существовал, но не должен менять уже сохраненный локальный снимок баллов, если продажа была создана офлайн раньше изменения настроек.

## Экран Руководителя

Экран `Продукты офиса`.

Возможности:

- посмотреть активные и скрытые продукты офиса;
- поиск по названию;
- фильтр по группам;
- включить или выключить продукт для офиса;
- изменить баллы;
- включить или выключить требование суммы;
- включить или выключить учет в плане;
- изменить порядок отображения;
- открыть историю изменений продукта.

Ограничения:

- руководитель офиса редактирует только свой офис;
- региональный руководитель выбирает офис внутри своего региона;
- админ может выбрать любой офис;
- сотрудник этот экран не видит.

## Экран Админа

Дополнительно к офисным настройкам админ видит `Глобальный справочник`.

Возможности:

- создать новый продукт;
- изменить название, группу и описание продукта;
- архивировать продукт;
- восстановить архивный продукт;
- массово включить продукт для выбранных офисов;
- открыть офисные настройки любого продукта.

Админ не вносит продажи от своего имени. Если админ одновременно является реальным сотрудником, для этого нужен отдельный сотруднический аккаунт или отдельная роль в будущем, но не в первой версии.

## История Изменений

Таблица `product_change_history`.

Поля:

- `id`
- `product_id`
- `org_unit_id`
- `changed_by_user_id`
- `changed_at`
- `field_name`
- `old_value`
- `new_value`
- `comment`

Писать историю нужно для:

- изменения баллов;
- включения или выключения продукта;
- изменения требования суммы;
- изменения учета в плане;
- изменения названия или группы глобального продукта;
- архивации и восстановления продукта.

## API

Продукты для сотрудника:

- `GET /api/products/active`

Управление офисными настройками:

- `GET /api/management/offices/{orgUnitId}/products`
- `PATCH /api/management/offices/{orgUnitId}/products/{productId}`
- `GET /api/management/offices/{orgUnitId}/products/history`

Глобальный справочник:

- `GET /api/admin/products`
- `POST /api/admin/products`
- `PATCH /api/admin/products/{productId}`
- `POST /api/admin/products/{productId}/archive`
- `POST /api/admin/products/{productId}/restore`

Продажи:

- `POST /api/sales/batch` должен принимать `productId` вместо старой enum-категории.
- На переходном этапе сервер поддерживает старое поле `category`, чтобы не сломать существующие данные и тесты.

## Миграция Из Текущей Версии

Сейчас продукты представлены enum-списком `ProductCategory` в Android и `CATEGORY_TITLES` на сервере. Их нужно перенести в таблицу `products`.

Переход:

1. Создать таблицу `products` и заполнить ее текущими продуктами.
2. Создать таблицу `office_product_settings`.
3. Для существующих офисов создать настройки по всем текущим продуктам.
4. Для продуктов `ПДС`, `ОПИФ`, `КСП` поставить `requires_amount = true`.
5. Для остальных продуктов поставить `requires_amount = false`.
6. Начальные баллы задать единым значением, пока руководитель не настроит офис.
7. Добавить поля-снимки в `sales`.
8. Для старых продаж заполнить снимки по старым категориям и текущим названиям.
9. Android заменить с enum-категорий на динамический список продуктов.

## Отчеты

Отчеты должны показывать:

- количество продаж;
- сумму по денежным продуктам;
- баллы по снимкам продаж;
- разбивку по продуктам;
- разбивку по сотрудникам;
- разбивку по офисам и регионам.

В отчетах по историческим периодам используются `product_title_snapshot` и `points_snapshot`, чтобы изменение справочника не переписало прошлые результаты.

## Ошибки И Защита

- Нельзя создать продукт с пустым названием.
- Нельзя создать два активных продукта с одинаковым `code`.
- Нельзя поставить отрицательные баллы.
- Нельзя сотруднику создать продажу по продукту, которого нет в его офисном списке.
- Нельзя руководителю менять офис вне его зоны доступа.
- Нельзя удалять продукт, если по нему есть продажи; только архивировать.
- Все изменения продуктов пишутся в журнал действий.

## Первый Объем Реализации

Сделать сначала:

- таблицы продуктов и офисных настроек;
- миграцию текущих продуктов;
- API активных продуктов для сотрудника;
- API редактирования офисных настроек;
- экран сотрудника на динамических продуктах;
- экран руководителя `Продукты офиса`;
- сохранение снимка баллов и названия в продажу;
- подсчет баллов в отчетах;
- историю изменений продуктовых настроек.

Отложить:

- массовые шаблоны настроек для региона;
- сложные согласования изменения баллов;
- отдельные продуктовые планы по каждому продукту;
- импорт продуктового справочника из Excel;
- серверную синхронизацию с боевой корпоративной системой.
